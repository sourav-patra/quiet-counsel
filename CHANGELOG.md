# Changelog

## 0.1.2 (2026-11-13)

- Security: `triage_flags.py` printed each flagged line and its neighbours as they stand in the file, so a triage run could put a credential or text aimed at the evaluator in front of an agent. A `secret-in-tree` flag now prints its location only. An `evaluator-directed-text` flag prints its location and a fixed notice; `--show-directed-text` prints the text when a person has asked for it. Any neighbouring line that holds a credential reads as withheld, under every flag, and the credential is never printed by any option (cases H-24 and H-25).
- Security: `triage_flags.py` judged each neighbouring line alone, so the base64 body of a private key printed beside another flag. Every line inside a BEGIN to END block is now withheld, found by reading the whole file, so a block whose opening marker is outside the requested context is still withheld (cases H-28 and H-29). The file path, title, flag id and error text of each item are tested for evaluator-directed text and credential shapes as source lines are, and print as a notice when they hold either (case H-30).
- Security: a file link in a scanned project that resolves outside the scanned root was followed, so the scan could read a file that is not part of the project. Such a file is now skipped, and the card lists each skip in its limits (the first 10 by path, the rest counted). Cases S-27 and S-28 skip, with the reason, on a system that refuses link creation.
- Security: the first fix covered only files the directory walk yields. Every other reader now goes through one containment test (`scan.contained`, with `leaves_root` recording the skip): the project's `.gitignore`, `.scanignore`, root instruction files, README, licence files, `package.json`, `pyproject.toml`, `requirements*.txt`, `.claude/settings.json`, `.vscode/tasks.json`, workflow files and their folder, the corpus licence and attribution files, recursive path patterns and the existence checks that decide a path is stale or present. The directory walk prunes a directory that resolves outside the root before it descends, so a junction is never listed or counted. The card names a skipped file as a file that was not read and a skipped directory as one that was not entered, and no longer says a path was not read when it was (cases S-29 to S-34; S-28 now requires the link itself to be cited).
- Security: three reads still left the scanned root. History and the commit id were read through whatever repository git found. The containment checks added for that were replaced by removing the reads (see the history entry below). A path pattern such as `src/**/*.py` in an instruction file was expanded by the file system before its matches were checked; it is now matched against the paths of the root's own walk, and a pattern that starts with `..` or at an absolute path is refused and listed (cases S-38 and S-39). The `review-project` fingerprint walk no longer enters a folder that resolves outside the project or hashes a file there (case S-40). The new cases record every path the code opens, lists or hands to git and assert that none is outside the root.
- Security: `triage_flags.py` now applies one credential test to every field it takes from the project: path, title, excerpt, error text, and the project path it prints when the directory is missing. A credential shape, or a credential word followed by an assignment and a value (`password=...`), is withheld; a word alone (`token_utils.py`) is not. A withheld path prints as `<path withheld>` with its line number. The flag id and severity are produced by the tool and are not tested. Neighbouring source lines use the same test (cases H-30 to H-32 and H-35); an earlier build withheld a credential word alone there, which hid ordinary lines that mention a token.
- History is disabled in 0.1.2 and returns in a later release with a contained design. Every version before this one read it by running the git program on the scanned project's own repository, and three review rounds kept finding more ways for that repository to name files for git to read or commands for it to run (a configuration include after a long prefix, a quoted alternate, `mailmap.file`, a promisor remote with `core.sshCommand`, links inside the metadata). The tool no longer starts any git program: `scan.git`, the metadata validators and the program-start overrides are deleted, and `quiet-counsel sample --git` is gone. The card reports history and provenance as not measured with the reason `disabled in 0.1.2` and says so in its limits; `signals.history` is `{available: false, reason: disabled in 0.1.2}`, `project.commit` is no longer written (the schema field stays optional), and `imported-first-commit` and `work-predates-event` are not raised. With `--event-start` the card lists a limit that the window was not checked. Case S-26 builds a repository with an include outside the root, a promisor remote whose ssh command writes a marker and a mail map outside the root, and checks that no git program starts, no outside path is read and the marker is never written; cases I-10 and I-12 and G-07 now check the not-measured report. The cases for the old containment checks (S-33, S-35 to S-37) and the shallow-clone and first-commit cases (I-11) are removed with the code they tested. The committed example changes by the history reason text, the missing `commit` key and one limit line.
- Security: output paths that bypassed withholding now use one shared rule (`scan.withhold_text`, the rule `triage_flags.py` already applied). `quiet-counsel classify` printed its evidence, including file names and quoted lines, as found, in text and in `--json`. `review_project.py prepare` wrote every file name and link target into the worksheet, `finalize` printed changed file names, and `verify` printed citations and excerpts. A credential, a credential word with an assignment and a value, or text aimed at the evaluator is now replaced by a notice in each of these. In the worksheet a withheld name carries a short hash of the real name, so `finalize` still sees an edit or a rename; the fingerprint itself keeps the real names (cases H-33 to H-35).
- Security: withholding now happens at one output boundary. Round 4 left four outputs that printed project text as found. Every artefact or stdout the tool or its skills emit passes through `scan.withhold_all`, which replaces a credential shape, a credential word with an assignment and a value, and text aimed at the evaluator with a notice, in keys as well as values; internal structures keep the raw values and the band, caps and scores are computed from them. `screen` returns its card through it (it used `redact_all`, which handled shapes only and is deleted with `redact`), so evaluator excerpts, classification evidence, paths and names are covered, and the cohort dashboard and the `prepare` worksheet inherit it; `integrity` filters its whole structure before printing (it prints JSON only); `finalize` filters the worksheet it rewrites and the card it renders, reviewer rationale and flag evidence included, and `dashboard.py` stays a renderer. A withheld reference loses its line number with the path, and a project whose own folder name is withheld is written to `project-N.json`, not to a name made of the notice. `triage_flags.py --show-directed-text` is unchanged: it lifts only the evaluator-text rule, per command, and never the credential rule. The committed example changes by 84 bytes in the scorecard and 72 in the dashboard, because its planted instruction is now a notice and no longer needs the replacement in `tools/gen_example.py`; `tools/check_evidence.py` accepts a notice for a line the filter withholds (cases H-36 to H-39 and M-09; S-18, S-25, X-03, E-02 and E-05 changed with it).
- Security: `finalize` compared the displayed file labels, which keep only 8 hex digits of a withheld name's hash, so a rename between two names whose labels collide passed unseen. The worksheet now stores `tree_ids`, the full SHA-256 of each raw path mapped to the full SHA-256 of its raw content digest or link target (the short labels stay for display), and `finalize` compares those, leaving out the review's own worksheet and verdict by the hash of their raw path. A worksheet from an earlier version has no `tree_ids` and is refused with a request to prepare again (case H-39).
- Security: round 5 left three commands that print what they load. `quiet-counsel dashboard` rendered the cards it read from files and `verdict` copied their flag ids, evidence paths, tag and commit, so a card from an older version or one a person edited could emit a credential or text aimed at the evaluator; both now pass the cards through `scan.withhold_all` first (the renderer is unchanged, and the verdict's `scorecard_sha256` is still the hash of the file as it stands). `check` printed schema problems that repeated card values (a version string, a flag id, a claim, a score); each problem is now a JSON path and a rule, and `schema.problems` repeats no value. `triage_flags.py` printed the flag id and severity of a loaded card as written, and `review_project.py` printed dimension ids from a loaded worksheet in `verify` and `finalize` lines; both now pass through the filter (case H-46). `tools/check_evidence.py` printed the raw project path and its citations, and `tools/selection_eval.py` copied skill names and descriptions into its prompt and a model's answer into its misses; both now filter what they print (cases H-40, H-41 and H-46).
- Security: `tools/selection_eval.py --skills DIR` expanded `DIR/*/SKILL.md` with a glob and opened every match, so a linked skill directory or a linked `SKILL.md` read a file outside `DIR` and put its frontmatter in the prompt. It now checks each directory and each `SKILL.md` against `DIR` before entering or opening it and names each skipped entry on stderr (case H-42).
- Security: card file names could collide, so one card silently replaced another: a withheld first project became `project-1.json` and a second project really called `project-1` wrote the same file. `quiet-counsel screen --out` and `screen_cohort.py` now choose every name over the whole cohort (`scan.card_file_names`: real names keep theirs, withheld ones become `project-N`, a clash gets `-2`, `-3`, compared without regard to letter case, a trailing dot or a reserved device name) and create each file exclusively. A file that already exists, such as one left by an earlier run in the same folder, stops the run with exit 2 and is not replaced; use a fresh folder (case H-43).
- `finalize` replaced a reviewer's excerpt of a sensitive line by a notice, and `verify` then compared the notice with the line and reported `MISMATCH` for a correct citation. `finalize` now stores `excerpt_sha256`, the SHA-256 of the raw excerpt, beside each notice it writes (an optional field of the scorecard schema), and `verify` reports `withheld, verified by digest` when a part of the cited line hashes to it. A wrong line, a changed line and a notice with no digest are refused (case H-44). `tools/check_evidence.py` now accepts a credential notice only for a line withheld as a credential and an evaluator-text notice only for a line withheld as evaluator text (case H-45). The committed example is unchanged.
- The three skills declared `license: Apache-2.0` while the repository is MIT. They now declare MIT, and `install.py` copies the repository `LICENSE` into each installed skill (case H-26). The skill descriptions are unchanged: the selection-eval prompt is byte-identical before and after.
- `triage_flags.py` stopped with `UnicodeEncodeError` on a non-UTF-8 console or pipe when a flagged line held a character that locale lacks, and needed `PYTHONUTF8=1` on Windows. It now sets its own output to UTF-8 (case H-27).
- Removed an unused import from `tests/test_safety.py`.

## 0.1.1 (2026-11-04)

- Security: 0.1.0 read history by running `git` with the scanned project's own `.git/config`, so a project that set `log.showSignature=true` and `gpg.program` to a script, and held a commit with a signature header, ran that script during `screen`. Every git call now puts overrides for the settings that start a program (signature checkers, pager, hooks path, file-system monitor, external diff) before the subcommand, and the script no longer runs (case S-26).
- Security: 0.1.0 did not read `.github` for the credential, evaluator-text, hidden-character, installer, licence or copy checks, because every directory whose name starts with `.git` was skipped. Only `.git` is skipped now, and those checks read `.github` (cases Z-10 and Z-11); other hidden directories are still skipped by them. The installer check filters quoted and defensive lines before it applies its budget of 60 hits, so 20 defensive comments no longer hide a real command, and a reached budget is reported (cases Z-13 and Z-14).
- Security: in 0.1.0 a repository's own `.scanignore` could lower its band, because findings in the paths it listed became information by default. A `.scanignore` now changes no flag, cap or band unless the person screening passes `--honour-ignore` for that one project; the card reports the file, its patterns and how many files they match. `--no-ignore` is still accepted and does nothing. A project with a `.scanignore` can move to a stricter band; none of the 50 repositories in the 2 November field run ships one.
- A check that stops at its hit, copy or file budget now says so: the card lists the check and the budget in its limits. For a check that decides a band, the card also carries a `scan-limit-reached` warning and the band is at least `review` (case I-32). For a check that only informs (the README flag check, eval evidence reads, result figure reads, and the listing of evaluator phrases that match only with case ignored) the card carries the limits entry and no flag, and the band does not change (cases Z-08, Z-09, Z-18). This reports a limit and does not close it; text past a budget is still not read. The character budgets count what was read before long lines are cut, so files of very long single lines use them up (cases Z-19 and Z-20). The root `.scanignore` is no longer read by any check, so it cannot use a budget (case I-26). A pattern prints in the signal only when it is path-shaped, patterns are deduplicated and capped at 50 (case I-33), and the licence stop no longer recounts its hits (case I-34).
- Four rule fixes found by the benchmark (`docs/BENCHMARK.md`): `evaluator-directed-text` phrases match whatever the letter case; `curl-pipe-shell` needs a whole-word shell after the pipe (`| sha256sum` and `| shellcheck` no longer match, `zsh` and `dash` do) and now reads `.github/workflows/*.yml`, including `run:` lines; `contradicted-claim` takes no count from "skill categories", "skill levels" or a sentence about a plan ("plan to", "will add", "roadmap"). Cases Y-01 to Y-05. Original-case matches are kept apart from case-only matches, so 25 case-only lines cannot hide a later original-case hit (case Z-17).
- A SPDX line now gets only the label its identifier names (`GPL-3.0` is GPL, `AGPL-3.0` is AGPL, `LGPL-2.1` is LGPL), in source files and in licence files (cases I-23 and I-28). In 0.1.0 one such line was listed once under each label. A licence file naming `AGPL-3.0` is now identified as AGPL, not GPL.
- The test helpers remove their temporary folders when the test process exits (case G-10).
- The test helpers retry `git add` up to four times when git reports `Permission denied` on a path in `.git/objects` with exit 128 (case G-11).
- Both README checks now report at information. After tightening, a run on 50 fresh repositories gave 2 flags (1 true, 1 false; the score flag covers 2 README lines, the mismatch flag 1), under the 5 needed to state a rate, so `readme-claim-mismatch` is no longer a warning. `docs/field-run-2026-11-03.json` holds the aggregates for the tuning and fresh samples.
- Tightened `readme-claim-mismatch` and `score-without-result` after the field adjudication (19 of 21 statements from the first 50 repositories were false). A flag is checked only when it follows the project's own command; command files, `SKILL.md` and shebang scripts count as files that can hold a flag; negated and reader-project paths and owner/repo or model-id tokens are skipped; a figure held by a result file under `docs/`, `benchmarks/` or `results/` clears `score-without-result`; "keep", "must" and script-scoped dependency wording is not a claim.
- New signal `eval_evidence` (`none`, `setup` or `result`, with the paths) and flag `score-without-result` (information, no cap): the README quotes a score, ranking or benchmark comparison and the repository holds no eval result file. A setup file alone is reported as setup. The flag says the result may be kept elsewhere and never says a claim is false. No measured false positive rate yet.
- New flag `readme-claim-mismatch` (information, no cap): the README names a licence, "no dependencies", a `--flag` or a path that the files contradict. Each flag cites the README line and the file or its absence. A field run on 50 fresh repositories gave 2 flags, too few for a rate.
- A `package.json` or `pyproject.toml` of the wrong types no longer ends the screen: the card names the metadata it left unchecked (cases Z-03 to Z-06).
- Elephant-Goldfish wording corrected.

## 0.1.0 (2026-11-02)

- First public release. Quiet Counsel reads an agent project's repository, works out its archetype
  (catalogue, harness, orchestrator, tool or application) from evidence, and writes a scorecard
  with the file and line behind each flag.
- Commands: `classify`, `screen`, `integrity`, `dashboard`, `check`, `verdict` and `sample`. The
  command reference is in `docs/cli.md`.
- Screening measures the rubric's dimensions as unverified. A deep pass, run by an agent with the
  `review-project` skill, scores them with evidence, applies the caps and renders the verdict.
- Agent interface: three skills (`screen-cohort`, `triage-flags`, `review-project`) and three
  roles (`screener`, `reviewer`, `verifier`), installed with `install.py`.
- Standard library only. It does not call a language model or any network service.
- Fixed a flag where a `"main"` string in any manifest counted as a package.json entry.
- Four checks written from public incident reports: `open-time-hook` (commands set to run when a
  folder or agent session opens), `install-time-script`, `workflow-data-out` and
  `untrusted-code-with-power`. Workflows are read line by line, not with a YAML parser; the limits
  are in `docs/test-suite.md`, Suite T.
- `open-time-hook` fires on session-start hooks and folder-open tasks only, and is serious only for a
  download piped to a shell or a script in a different host folder. Other hook events raise an
  information-level `agent-hook`. Evaluator-directed text and copyleft text found only under test
  paths are lowered (serious and warning) and still listed.
- A project's `.scanignore` cannot lower the critical `evaluator-directed-text` flag. The listing limit for
  that flag applies after the defensive-text and test-path tests. A settings file or manifest nested too
  deeply to read raises `unreadable-configuration`. `runOn` is read from parsed tasks, not from comments.
- Evaluator-directed lines judged to be quoted or defensive are listed as `quoted-evaluator-text` at
  information level, with file, line and count, instead of being dropped. `untrusted-code-with-power`
  treats `secrets: inherit` on a reusable-workflow call as holding secrets.
- `tools/check_evidence.py` counts how many flags and numeric signals cite a file and line that
  exist.
- The dashboard and the screen's limits note said every flag names a file and line. Flags about history or a
  missing file cite a command or commit, so both now say every flag names its evidence. `stale-instructions`
  no longer raises on a bare workflow name that exists under `.github/workflows/` (cases Q-12, Q-13, V-10).
- A source line that holds a credential shape, or a word such as `secret`, `token` or `password`,
  is no longer partly quoted with its value masked. The card quotes none of it: the excerpt reads
  `<line withheld>` and the flag keeps its file and line. Every other line is quoted as written.
  This guards against accidents; a repository written to defeat it can still get text onto a card.
  `tools/check_evidence.py` counts these lines as `withheld`. `quiet-counsel integrity` no longer
  prints a whole line it would withhold from a card, and flags are listed in a fixed order
  (cases S-25, M-04, M-07, M-08). A `.scanignore` pattern shown in a card, a hook event name in
  the `agent-hook` detail and a stale path beside a fenced span follow the same rule (case S-25).
- A release-review workflow is not in 0.1. The `verdict` command stays.
- Not yet proven on a real cohort. The field checks are listed in `docs/test-suite.md`.
